Feed: DT_SCHEDULE_UPDATE (source: OVR)

One Kafka message per schedule update. Key path: value.competition.unit[] — each array item is one match unit. The outer value carries metadata (competitionCode, logicalDate, source).

Source: athlete[] nested in DT_SCHEDULE_UPDATE or DT_PARTIC_UPDATE

Player/athlete data arrives embedded inside competitor compositions. Path: unit[n].startList.start[n].competitor.composition.athlete[]. Each athlete object contains the full profile (name, DOB, nationality, gender).

EntityJSON PathWSC TargetKey Fields
Athlete competitor.composition.athlete[n] WSC Player code, givenName, familyName, organization, gender, birthDate, ifId
{ "code": "200124", "order": 1, "description": { "givenName": "Mark", "familyName": "GERGELY", "organization": "HUN", "gender": "M", "birthDate": "2010-02-22", "ifId": "200124", "class": null } }
→ code — WSC PlayerExternalId (ITTF player ID)
→ ifId — same as code in standard cases
→ givenName + familyName → WSC PlayerName
→ organization = "HUN" — IOC nationality code
→ gender = "M" — M / F
→ birthDate = "2010-02-22" — ISO 8601 date
→ order — position in team (1 = first player, 2 = second in doubles)

Note: In singles, 1 athlete per competitor. In doubles, 2 athletes per competitor — iterate array, do not access [0] directly.
Athlete (doubles) competitor.composition.athlete[1] WSC Player (partner) code, order=2 — second player in a doubles pair
// From DT_PARTIC_TEAMS_UPDATE — doubles pair Aron KANLIC / Ana SLADOJE { "composition": { "athlete": [ { "code": "200152", "order": 1 }, { "code": "202704", "order": 2 } ] } }
→ athlete[0].code = "200152" — first player in pair (Aron KANLIC)
→ athlete[1].code = "202704" — second player (Ana SLADOJE)
→ order — 1 = primary, 2 = secondary

In doubles, both athlete codes must be resolved to WSC PlayerIds independently. The team code ("100175986") is the team entity — distinct from the individual player codes.

Feed: DT_PARTIC_TEAMS_UPDATE (source: OES)

One Kafka message contains the full teams participation list. Key path: value.competition.team[] — each item is a registered doubles pair or team. Carries ranking, seeding, event entry, and athlete composition.

EntityJSON PathWSC TargetKey Fields
Envelope value (top-level) Feed metadata documentType, competitionCode, source, modificationIndicator

→ documentType = "DT_PARTIC_TEAMS_UPDATE" — route to teams handler
→ source = "OES" — participation data comes from OES (not OVR)
→ language = "ENG" — text fields are in English
Team value.competition.team[n] WSC Team / DoublesEntry code, name, organization, category, modificationIndicator, composition.athlete[]

→ code = "100175986" — WSC TeamExternalId
→ name — display name for the doubles pair
→ organization = "BIH" — IOC country code. Can be combined ("CZE/BUL") for mixed-nationality pairs
→ gender = "X" — mixed doubles (M = men, F = women, X = mixed)

→ modificationIndicator — "U" update, "N" new, "D" delete

Team Entry team[n].discipline.registeredEvent Event Registration event (code), eventEntry[] — SEED, QUAL_TYPE, DRAW, RANK_WLD, RANK_PTS
{ "discipline": { "code": "TTE-------------------------------", "registeredEvent": { "event": "TTEXDOUBLES--------U19------------", "eventEntry": [ { "code": "SEED", "value": "0" }, { "code": "QUAL_TYPE", "value": "AER" }, { "code": "DRAW", "value": "Main Draw" }, { "code": "RANK_WLD", "value": "29" }, { "code": "RANK_PTS", "value": "5067" } ] } } }
→ event = "TTEXDOUBLES--------U19" — event code the team is registered for
→ SEED — seeding number (0 = unseeded)
→ QUAL_TYPE = "AER" — qualification type (AER = automatic entry by ranking)
→ DRAW = "Main Draw" — draw placement
→ RANK_WLD = "29" — world ranking at time of entry
→ RANK_PTS = "5067" — ranking points

eventEntry is a flat key-value array — iterate and map by code field.
Deletion team[n].modificationIndicator = "D" WSC Team (delete) modificationIndicator="D" — team withdrawn/removed from event
{ "code": "100244153", "name": "Paul FLEMMING/Sara RIVETTI", "organization": "GER/CRO", "modificationIndicator": "D", "category": "U15" }
→ modificationIndicator = "D" — this team was deleted/withdrawn
→ "U" = update existing, → "N" = new entry

Always check modificationIndicator before upserting. "D" records should trigger soft-delete or deactivation in WSC, not an insert.
